# 인증 · 온보딩 · 공통 레이아웃

처음 온 사용자에게 서비스를 소개하고 소셜 로그인으로 가입시킨다. 로그인한 사용자만 서비스를 쓰게 막는다.
모든 화면에 공통으로 적용되는 하단 탭바와 앱 설치 안내도 여기서 다룬다.
개념·용어는 [product.md](../product.md) 참고. 로그아웃·탈퇴는 [profile.md](./profile.md), ZTPI 테스트는 [ztpi.md](./ztpi.md)에서 다룬다.

코드에서 추론했고 기획 의도가 확정되지 않은 규칙은 `[확인 필요]`, 코드가 의도와 다르게 동작하는 것으로 보이는 부분은 맨 아래 "확인 필요 — 버그 의심"에 모은다.

## 규칙

### 인증 가드 (모든 페이지 공통)

- `/login`, `/onboarding`, `/test-auth`를 뺀 모든 페이지는 로그인해야 들어갈 수 있다
- 페이지에 들어올 때 로그인 상태를 이렇게 판단한다
  - 로그인 토큰이 유효하면 → 그대로 진입
  - 토큰이 없거나 만료됐지만 로그인 연장 토큰이 있으면 → 로그인을 연장한 뒤 같은 주소로 다시 진입
  - 로그인 연장 토큰도 없으면 → `/onboarding`
  - 로그인 연장에 실패하면 → `/login` (연장 토큰 삭제)
- 토큰 만료 5초 전부터 만료된 것으로 본다
- 페이지를 쓰는 도중 API가 401을 주면 로그인을 한 번 연장하고 같은 요청을 다시 보낸다. 요청 여러 개가 동시에 401을 받아도 연장은 한 번만 한다

### 홈 진입 조건

- 사용자 정보 조회에 실패하면 → `/login`
- ZTPI 테스트를 마치지 않은 사용자(`isOnboarded: false`)는 → `/ztpi-test`

### 온보딩 (`/onboarding`)

- 서비스 소개 화면을 여러 단계로 보여준다. 단계별 제목·설명·이미지는 서버에서 받는다
- 상단 진행 바에 현재 단계까지 채워져 보인다
- 첫 단계에서는 "이전" 버튼이 없고 "다음"만 보인다
- 마지막 단계에서 "다음"을 누르면 `/login`으로 간다
- 터치 화면에서 좌우로 50px 이상 밀면 다음 / 이전 단계로 넘어간다 (마우스 드래그는 안 됨)
- `?step=N`으로 들어오면 N단계부터 보여준다. 1보다 작거나 숫자가 아니면 1단계, 전체 단계보다 크면 마지막 단계

### 로그인 (`/login`)

- "시간 성향에 맞춘 나만의 회고" 문구와 로그인 버튼 3개가 보인다: "카카오로 시작하기" / "네이버로 시작하기" / "Google로 시작하기"
- 버튼을 누르면 해당 소셜 로그인 화면으로 이동한다
- [확인 필요] 소셜 로그인을 마친 뒤 돌아오는 화면(홈? ZTPI 테스트?)과, 로그인 취소·실패 시 돌아오는 화면

### 하단 탭바 (공통)

- 탭은 왼쪽부터 홈(`/`) / 캘린더(`/calendar`) / 통계(`/statistics`) / 그룹(`/groups`) / 프로필(`/profile`) 5개다. 아이콘만 있고 글자는 없다
- 누르면 해당 화면으로 이동한다
- 현재 화면의 탭이 활성 아이콘으로 바뀐다
  - 홈 탭은 `/`에서만 활성이다
  - 나머지는 주소가 탭 경로로 시작하면 활성이다 (예: 친구 회고 `/groups/…`에서는 그룹 탭)
  - 어느 탭에도 해당하지 않는 화면(예: 회고 상세 `/reflection/[id]`)에서는 홈 탭이 활성이다
- 탭바가 보이는 화면: 홈, 캘린더, 통계, 그룹 목록, 친구 회고, 회고 상세, 마이페이지, 테마 선택
- 탭바가 없는 화면: 온보딩, 로그인, ZTPI 테스트·결과, 캐릭터 소개, 회고 작성, 피드백, 보상, 그룹 생성·수정, 닉네임 변경, 알림 목록
- [확인 필요] 탭 버튼의 접근성 이름이 영문 키(`home`, `calendar` 등)다. 스크린리더용 한글 이름이 필요한지

### 앱 설치 안내 (모든 페이지 공통)

- iPhone·iPad에서 홈 화면 앱이 아닌 브라우저로 접속하면 0.5초 뒤 "앱 설치하기" 안내가 뜬다
  - 일반 브라우저: "공유 버튼 클릭" → "홈 화면에 추가" 순서 안내
  - 카카오톡·인스타그램 등 인앱 브라우저: "현재 브라우저에서는 앱 설치가 지원되지 않아요" + 크롬·사파리로 열라는 안내
- "나중에"나 바깥을 누르면 닫힌다. "다시 보지 않기"를 체크하고 닫으면 같은 브라우저에서는 다시 뜨지 않는다

### 테스트 로그인 (`/test-auth`)

- 이메일만 입력해 로그인하는 개발·QA용 화면이다. 성공하면 홈으로 간다
- "토큰 재발급" 버튼으로 로그인 연장을 직접 시험할 수 있다

## 예외

- 온보딩 소개 불러오기 실패 → "온보딩 소개를 불러오지 못했어요." + "다시 시도하기"
- 홈 화면에서 예상하지 못한 오류 → "문제가 발생했어요." + 다시 시도
- [확인 필요] 이미 로그인한 사용자가 `/login`이나 `/onboarding`에 들어오면 홈으로 보내지 않고 그대로 보여준다. 의도인지
- [확인 필요] 페이지 사용 중 로그인 연장이 실패하면 로그인 화면으로 보내지 않고 해당 API 오류로만 처리된다(각 화면의 에러 상태가 보임). 다른 페이지로 이동할 때 인증 가드가 위 규칙대로 `/login`이나 `/onboarding`으로 보낸다. 의도인지

## 확인 필요 — 버그 의심

- **`/test-auth`가 운영 환경에서도 열려 있다.** 코드에 "임시로 프로덕션에서도 허용" 설정이 켜져 있다. 백엔드가 이메일만으로 로그인을 허용하면 누구나 아무 계정으로 로그인할 수 있으므로 백엔드 제한 여부를 확인해야 한다
